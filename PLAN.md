# canvas-mcp — Plan

Read-only MCP server for Reykjavík University Canvas (`reykjavik.instructure.com`) plus a
sync engine that mirrors course material into `~/Documents/Tolvunarfraedi/onn N/<course>/canvas/`.

## Goals (from user)
1. Assignments: list, filter (upcoming / missing / graded), full detail incl. description + rubric.
2. Calendar / upcoming: everything due or scheduled — assignments, quizzes, calendar events, planner items.
3. All course files (slides, PDFs, handouts) + Canvas Pages mirrored to disk, organised by
   Canvas folder / module, into `<course>/canvas/`.
4. Course folders named by course-code suffix in lowercase (`T-603-THYD` → `thyd`). Existing
   folders in `onn 5/` (`POSH`, `compilers`, `tsam`, `veft`) get renamed to match, after user confirms.
5. Read-only against Canvas. No submissions, no posting.

## Constraints / decisions
- TypeScript, Node ≥ 22, `@modelcontextprotocol/sdk`, stdio transport. ESM.
- Token from `.env` (`CANVAS_TOKEN`, `CANVAS_BASE_URL`). Never logged, never committed.
- `SCHOOL_ROOT` default `~/Documents/Tolvunarfraedi`. Semester folder `onn <N>` where N comes
  from config (`CURRENT_SEMESTER=5`), not guessed.
- Pagination via `Link: rel="next"` on every list call, `per_page=100`.
- Respect `X-Rate-Limit-Remaining`; back off below 50, retry on 403 rate-limit / 5xx.
- In-memory cache with TTL (courses 1h, assignments 10m, files 10m) — server is short-lived per session.
- Sync is idempotent: manifest (`<course>/canvas/.canvas-sync.json`) records file id → path,
  `updated_at`, size. Skip unchanged, re-download changed, never delete user files. Files removed on
  Canvas are left in place (reported, not deleted).
- Course mapping lives in `config/courses.json`: `{ "<canvas_course_id>": { "code": "T-603-THYD", "slug": "thyd", "semester": 5 } }`.
  Generated by `propose_course_mapping`, confirmed by user.

## Architecture
```
src/
  index.ts            MCP server entry (stdio). Registers tools. No business logic.
  config.ts           env + courses.json loading, path helpers (semesterDir, courseDir).
  canvas/
    client.ts         fetch wrapper: auth, pagination, rate-limit, retries, cache. get<T>(path, params), getAll<T>(path, params).
    types.ts          Canvas API types (Course, Assignment, File, Folder, Module, ModuleItem, Page, PlannerItem, CalendarEvent, Announcement, Enrollment).
    courses.ts        listActiveCourses(), slugFromCode()
    assignments.ts    listAssignments(courseId, filter), getAssignment(courseId, id), submissions summary
    calendar.ts       upcoming(days): planner items + calendar events + assignment due dates, merged + sorted
    files.ts          listFolders/listFiles (recursive), downloadFile(file, destPath) (handles expiring URL)
    modules.ts        listModules(courseId) with items
    pages.ts          listPages, getPage (html→markdown)
    announcements.ts
    grades.ts         enrollments?user_id=self → current score per course
  sync/
    mapping.ts        proposeMapping(courses, existingFolders) — fuzzy match to current folder names; applyRename(plan)
    engine.ts         syncCourse(courseId, opts): walks Files tree + Modules + Pages → writes to <course>/canvas/{files,modules,pages}/
    manifest.ts       load/save/diff
  tools/              one file per MCP tool, thin: validate input (zod) → call canvas/* → format
  util/
    html.ts           html → markdown (turndown)
    fs.ts             safe paths, sanitize filenames (keep Icelandic chars), atomic write
tests/
  fixtures/           recorded JSON responses (anonymised)
  *.test.ts           vitest; client pagination, rate-limit backoff, mapping proposals, sync idempotency (tmp dir)
```

## MCP tools (v1)
| tool | input | returns |
|---|---|---|
| `list_courses` | `{ include_past?: bool }` | id, code, slug, name, term |
| `list_assignments` | `{ course?: slug\|id, filter?: "upcoming"\|"past"\|"missing"\|"graded"\|"all", days?: n }` | compact list, due date, points, submitted?, score |
| `get_assignment` | `{ course, assignment_id }` | full description as markdown, rubric, attachments, submission state |
| `get_upcoming` | `{ days?: 14 }` | merged timeline: assignments, quizzes, events, announcements — grouped by day |
| `list_announcements` | `{ course?, days?: 30 }` | title, date, body markdown |
| `get_grades` | `{}` | per course current score / grade |
| `list_modules` | `{ course }` | modules with items (type, title, file id / page url) |
| `search_materials` | `{ query, course? }` | ranks files + module items + pages by name match; returns local path if already synced |
| `get_page` | `{ course, page_url }` | page body as markdown |
| `download_file` | `{ course, file_id, dest? }` | downloads single file to `<course>/canvas/files/...` (or dest), returns path |
| `propose_course_mapping` | `{ semester }` | proposed `courses.json` + folder rename plan (old → new), does NOT apply |
| `apply_course_mapping` | `{ confirm: true }` | writes `courses.json`, renames folders (fails if target exists) |
| `sync_course` | `{ course \| "all", dry_run?: bool }` | downloads new/changed files, modules, pages; report of added/updated/skipped |
| `sync_status` | `{ course? }` | manifest summary, last sync time, stale count |

Also a CLI: `npx canvas-mcp sync [slug|all] [--dry-run]` and `npx canvas-mcp courses` — same code path as the tools.

## Phases
1. **Scaffold + client** (1 sonnet agent): package.json, tsconfig, eslint-lite, `config.ts`, `canvas/client.ts`, `canvas/types.ts`, tests for pagination/rate-limit with mocked fetch.
2. **Parallel** (3 sonnet agents, disjoint files):
   - A: `canvas/{courses,assignments,calendar,announcements,grades,pages}.ts` + tools for them + `util/html.ts`
   - B: `canvas/{files,modules}.ts` + `sync/*` + `util/fs.ts` + sync/download tools + CLI
   - C: `tools/search_materials.ts`, `index.ts` registration, README, Claude Desktop / Claude Code registration snippets, `.env.example`
3. **Review** (2 opus agents): one reviews correctness/security (token handling, path traversal, rate limits), one reviews API-shape/UX of tools vs the goals above. Both file concrete fixes; coders apply.
4. **Integration test by lead** with the real token: list courses → propose mapping → user confirms rename → sync all → spot-check files on disk → register in Claude Desktop.

## Out of scope v1
Submissions, discussions posting, quizzes content, groups, background launchd sync (easy add later).

## Live findings (verified against real Canvas, 2026-09-08)
- Course code format: `T-NNN-CODE` (e.g. `T-603-THYD`). slug = lowercase last segment (`thyd`). Some have prefixes like
  `X-204-STOF` — same rule. Courses whose `course_code` does NOT match `/^[A-Z]-\d{3}-[A-Z0-9]+$/` are NOT real
  courses (RU-ANNOUNCE, TVIUND, "Myndbönd …" video shells) → exclude from everything except `list_courses(include_all)`.
- Term names: `Haustönn 2024`, `Vorönn 2025`, `Haustönn 2025`, … Semester number is DERIVED from the term:
  `FIRST_TERM = "Haustönn 2024"` (env, default) = önn 1; each subsequent Vorönn/Haustönn increments. Haustönn 2026 = önn 5.
  Term comes from `include[]=term` on `/api/v1/courses`. "Default term" → no semester (exclude).
- `enrollment_state=active` still returns a stale prior-term course (T-304-CACS, Haustönn 2025). "Current" courses =
  those whose derived semester == max derived semester among active courses, not simply enrollment_state=active.
- Semester 5 courses: 10488 T-503-POSH, 10483 T-409-TSAM, 10492 T-514-VEFT, 10487 T-488-MAPP, 10495 T-603-THYD.
- Existing folders in `onn 5/`: `POSH`, `compilers`, `tsam`, `veft`. Desired: `posh`, `thyd`, `tsam`, `veft`, `mapp`.
  `POSH`→`posh` is a CASE-ONLY rename on a case-insensitive filesystem (APFS default): must rename via a temp name
  (`POSH` → `posh.__tmp` → `posh`). `compilers`→`thyd` cannot be matched by string similarity — mapping proposal
  must support explicit `overrides: { "compilers": "thyd" }` and must list unmatched folders + unmatched courses
  so the user can fill gaps. Auto-match rules: folder name (lowercased, accents stripped) equals slug, OR equals an
  accent-stripped word of the course name (`styrikerfi` ~ `Stýrikerfi`, `gervigreind` ~ `Gervigreind`).
- User id <redacted>. `/api/v1/users/self` works → use as auth smoke test.

## Live findings round 2 (2026-09-08, after Phase 2 launch) — MUST be applied in review
1. **Files tab hidden for students in 4/5 courses** (THYD, VEFT, POSH, MAPP): `GET /courses/:id/files` and
   `GET /folders/:id/files` → 403 `{"status":"unauthorized"}`. Only TSAM lists files directly.
   BUT: `GET /courses/:id/folders` works everywhere (gives ids + `full_name`), and `GET /api/v1/files/:id` works for any
   file the student can reach (returns display_name, folder_id, size, updated_at, url, locked_for_user).
   → `listAllFiles(client, courseId)` must: try `/courses/:id/files`; on 403 fall back to a **discovered set**:
   every module item with `type === "File"` (`content_id` = file id) + every `/courses/:id/files/:id` or `/files/:id`
   link found in page bodies and assignment descriptions; fetch each via `/api/v1/files/:id` (dedupe, small
   concurrency), then join with the folders list for `folderPath`. Add `source: "listing" | "discovered"` to
   FileEntry so tools can tell the user the list may be incomplete. Sync/search must work in both modes.
2. Folder `full_name` format confirmed: `course files/Slides`, `course files/TEMPLATE FILES/Images/Icons` (150 junk
   icons). Skip any folder path whose first segment is `TEMPLATE FILES` in sync and search.
3. Module items with `include[]=content_details` give `content_details.display_name` and `url` =
   `/api/v1/courses/:id/files/:fid` for File items. `items` was present for modules of 6–9 items; still keep the
   `/modules/:id/items` fallback when `items` is absent.
4. Planner items already include `calendar_event` (lectures: "V104 - Þýðendur - Fyrirlestrar", dæmatímar) and
   `announcement` types, so `/calendar_events` is only a redundancy; dedupe on (type, id). 65 planner items in Sept.
   `submissions` is `false` for non-submittables, else an object with `submitted`/`graded`/`missing`.
5. Grades: `grades.current_score` is null for every enrollment, and `include[]=total_scores` gives null too — RU hides
   course totals from students. `get_grades` must say "Course totals hidden by RU — showing per-assignment scores
   instead" and fall back to summing graded assignments (score / points_possible) per course.
6. Assignments use `submission_types: ["none"]` / `["on_paper"]` with `workflow_state: "graded"` and `submitted_at:
   null` — so "submitted" must be derived as `submission.workflow_state in (submitted, graded, pending_review)` OR
   `score != null`, NOT from `submitted_at`.
7. Announcements need `start_date`; POSH has 3 since Aug, THYD 0. Body in `message` (HTML).
8. Pages exist in every course but are mostly RU template pages (`course-home-page`, `template-information`,
   `assessment`, `teaching-methods`). Still sync them; they're small.
